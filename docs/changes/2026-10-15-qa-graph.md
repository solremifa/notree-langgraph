# 2026-10-15 실험: Q&A 근거 탐색 그래프 (`feat/qa-graph` 브랜치)

> **main에 아직 합치지 않은 실험입니다.** 아래 "merge 기준"을 팀이 보고 결정합니다.

## 왜 그래프로 만드나

Q&A에서 근거를 찾는 순서(노트 → 강의 전사 → 웹)와 멈추는 조건은 **제품 정책**입니다.
이걸 프롬프트로 "먼저 노트를 보고…"라고 시키면 LLM이 순서를 건너뛰거나, 웹을 여러 번 부르거나, 근거에 없는 내용을 인용해도 막을 방법이 없습니다.
그래프로 만들면 정책이 코드 구조가 됩니다.

| 정책 | 그래프에서 강제하는 방법 |
|---|---|
| 노트에서 충분하면 거기서 멈춤 | `search_note` 뒤 분기: 최고 점수 ≥ 0.6이면 바로 `answer` |
| 애매한 근거도 LLM이 판단 | 멈춤 기준(0.6)과 별도로, 0.3 이상인 근거는 모두 LLM에게 줌 |
| 웹은 최대 1번 | `search_web` 노드가 하나뿐이고 되돌아가는 간선이 없음 |
| 마감이 가까우면 비싼 단계 건너뜀 | 전사는 남은 시간 ≥ 10초, 웹은 ≥ 25초일 때만 (`skip_*` 노드가 이유를 남김) |
| 근거에 없는 인용 금지 | `verify`가 인용 ID를 이번에 찾은 근거와 대조, 틀리면 1번 다시 답하고 그래도 틀리면 "근거 부족"으로 저장 |
| 출처 라벨(강의/웹/일반 지식/근거 부족) | LLM이 **실제로 인용한** 근거의 출처로 정함 (인용 없으면 근거 부족) |

LLM이 하는 일은 **질문 이해(관련 여부·검색어)** 와 **주어진 근거로 답하기** 두 가지뿐입니다.

## 그래프

```
START → understand ─(관련 없음)─────────────────────────────→ answer
            └→ search_note ─(충분)───────────────────────────→ answer
                   ├(부족·10초 이상)→ search_transcript ─(충분)→ answer
                   │                      ├(부족·25초 이상)→ search_web → answer
                   │                      └(부족·시간 없음)→ skip_web → answer
                   └(부족·시간 없음)→ skip_transcript → answer
answer → verify ─(통과 또는 재시도 소진)→ save → END
            └(인용 문제·재시도 남음)→ answer
```

`uv run python -m notree.dev.qa_run --graph`로 Mermaid 그림을 볼 수 있습니다.

## 코드

| 파일 | 내용 |
|---|---|
| `notree/graphs/qa/state.py` | 상태. `hits`·`searched`·`skipped`는 단계마다 덧붙임(reducer) |
| `notree/graphs/qa/retriever.py` | `Retriever` 인터페이스, `FakeRetriever`(키워드 일치 점수), 데모용 '자료구조' 말뭉치 |
| `notree/graphs/qa/llm.py` | `FakeQALLM`, `OpenAIQALLM`(JSON 응답 + pydantic 검사) |
| `notree/graphs/qa/graph.py` | 노드·분기·`build_qa_graph()`, 기준값 `ENOUGH_SCORE`·`TRANSCRIPT_MIN_SEC`·`WEB_MIN_SEC`·`MAX_ANSWER_ATTEMPTS` |
| `notree/dev/qa_run.py` | 단계별 진행을 찍는 데모 |
| `tests/test_qa_graph.py` | 분기별 테스트 13개 |

실행에 필요한 것(`llm`, `retriever`, `deadline_at`, `sink`)은 `config["configurable"]`로 넘깁니다.
그래서 worker에서는 MCP 검색 도구를 부르는 Retriever와 `qa_complete`를 부르는 sink만 꽂으면 됩니다.

**체크포인트는 쓰지 않습니다.** rt 작업이라 90초 안에 끝나고, 중간에 죽으면 처음부터 다시 하는 게 더 단순합니다 (그때 LLM 호출 2~3번이 다시 일어남).
진행 상황은 `astream(stream_mode="updates")`로 받아 화면에 "노트에서 찾는 중…"처럼 보여줄 수 있습니다.

## 돌려 보기

```powershell
uv run python -m notree.dev.qa_run                                              # 노트 / 전사 / 웹 / 관련 없음
uv run python -m notree.dev.qa_run "힙 정렬의 시간 복잡도는?" --deadline-in 15   # 웹 건너뜀 → 근거 부족
uv run python -m notree.dev.qa_run "스택은 어떤 구조야?" --bad-citation          # 틀린 인용 → 다시 답하기
uv run python -m notree.dev.qa_run "스택은 어떤 구조야?" --llm openai            # 실제 LLM (검색은 가짜)
uv run pytest -q tests/test_qa_graph.py
```

## 확인한 것 (가짜 LLM·가짜 검색)

| 질문 | 검색한 곳 | 결과 |
|---|---|---|
| 스택은 어떤 구조야? | 노트 | 강의, [n1] |
| 스택 오버플로는 왜 생겨? | 노트 → 전사 | 강의, [t1] |

| 스택 오버플로… (마감 5초 전) | 노트, 전사 건너뜀 | 근거 부족 |

| 매번 없는 ID 인용 | 노트 | 2번 시도 후 근거 부족, 인용 비움 |

## 실제 LLM으로 돌려 본 결과 (gpt-4o-mini, 검색은 가짜 말뭉치)

첫 실행에서 나온 문제와 고친 것:

| 문제 | 원인 | 수정 |
|---|---|---|
| answer 단계 400 오류 | JSON 모드는 메시지에 'json'이라는 단어가 필요한데 답변 프롬프트에 없었음 | 모든 요청에 JSON 지시 system 메시지 |
| 정답 근거를 찾고도 "근거 부족" (오버플로·힙 정렬 질문) | LLM이 `자료구조`, `메모리` 같은 일반 검색어를 붙여 점수가 0.5로 내려갔고, **멈춤 기준 0.6이 LLM에게 줄 근거까지 걸러서** 정답 근거가 전달되지 않음 | 기준 분리(멈춤 0.6 / 전달 0.3), 라벨은 인용한 근거로, 검색어 프롬프트에 "일반 단어 빼고 2~4개" |
| 근거 부족인데 내용을 추측해서 답함 | 프롬프트가 약함 | "추측하지 말고 근거를 찾지 못했다고만" |

가짜 검색은 검색어가 늘수록 점수가 떨어지는 방식이라 실제 검색과 다르지만, **점수가 애매하게 나오는 정답 근거**는 실제 임베딩 검색에서도 흔합니다.
그래서 "더 찾을지"와 "LLM에게 보여줄지"를 같은 기준으로 정하면 안 된다는 것이 이번에 배운 점입니다.

## 확인하지 못한 것

- 실제 검색 품질. 가짜 검색은 "검색어가 몇 개 들어 있나"로 점수를 매기므로, 0.6이라는 기준값은 **실제 임베딩 점수로 다시 정해야** 합니다.
- worker 연결. `qa` 핸들러는 아직 스텁이고, 연결하려면 검색 MCP 도구(`notes_search`, 전사 검색, `web_search`)와 `qa_complete`가 먼저 필요합니다.

## merge 기준 (팀 결정)

아래가 맞으면 main에 합칩니다.

1. **정책이 맞는가**: 노트 → 전사 → 웹 순서, 웹 1번, 시간 기준(10초/25초), 인용 재시도 1번, 라벨 4종이 기획과 같은지
2. **실제 LLM으로 한 번 돌려 봄**: `--llm openai`로 기본 질문 4개를 돌려 understand의 관련 여부·검색어와 인용이 쓸 만한지
3. **API 쪽과 합의**: 저장 결과 형식(`answer`, `citations`, `label`, `status`)과 진행 상황 표시(노드 이름) — `qa_complete` 계약에 반영
4. **기준값을 어디서 정할지**: 충분 점수 0.6 같은 값은 실제 검색이 붙으면 바뀌므로 `common/settings.py`로 옮길지

합친 뒤 할 일: 검색 MCP 도구 계약 확정 → `McpRetriever` → `qa` 핸들러 연결 → 노트 제안 단계는 별도 batch 작업으로.
