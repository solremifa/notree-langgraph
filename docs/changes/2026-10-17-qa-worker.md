# 2026-10-17 변경 정리: Q&A worker 통합 1·2단계 (`feat/qa-worker`)

진행 순서(`docs/status.md`)의 Q&A 통합 중 **1. 검색·저장 도구 계약 확정**과 **2. 가짜 도구로 worker–그래프 연결**입니다.
질문 하나가 등록부터 답변 저장·화면 조회까지 끝나는 경로를 만들었습니다. 검색은 PoC 가짜(SQLite 키워드 일치), LLM은 가짜가 기본입니다.
노트 반영 제안(proposal)과 사용자 승인은 첫 통합에서 뺐습니다.

## 흐름

```
api   qa_ask(user, course, question) ── 한 트랜잭션: 질문 행 + qa 작업 의도(마감 = 요청 + 90초)
        → 배정기(qa 레인) → Redis notree:qa → qa worker
worker qa 핸들러
        1. qa_context        질문·과목 이름·강의 목록·세대
        2. Q&A 그래프         검색은 McpRetriever: 노트·전사 → qa_search, 웹 → web_search
        3. qa_complete       결과 저장 (idem_key = job_id, expected_generation = 1의 세대)
        → job_finish → XACK
api   qa_get(question, user) ── 화면 조회: pending / answered / deleted + 저장된 결과
```

## 도구 계약 (`notree/contracts/tools.py`, 문서 `docs/tool-contracts.md`)

| 도구 | 부르는 쪽 | 하는 일 |
|---|---|---|
| `qa_ask` | api | 질문 저장 + qa 작업 의도를 한 트랜잭션에 |
| `qa_context` | worker | 질문, 과목 id·이름, 강의 목록, 질문 세대, (최근 대화: 첫 통합에선 빈 목록) |
| `qa_search` | worker | `source`(note·transcript), `keywords`, `limit`, `lecture_ids`(전사 우선 범위용, 선택) → 근거 `{id, source, text, score, ref, lecture_id}` |
| `web_search` | worker | 웹 1회. `question_id`를 받아 사용자·과목을 안다 (한도·감사용). PoC는 시드한 web 문서에서 찾음 |
| `qa_complete` | worker | 결과 저장: `status`, `label`, `answer`, `sentences`, `sources`, `notice_code`. 멱등, 세대 확인, 실행권 확인 |
| `qa_get` | api | 화면 조회 |
| `qa_delete` | api | 질문 삭제 (세대 증가) |
| `qa_seed` | dev | PoC 검색 문서 넣기 |

- 결과 필드는 Q&A 결과 형식 문서(`status` 4종, `label` 4종, `notice_code` 3종, `sources`는 인용된 근거만)와 같습니다. 서버가 계약 모델로 값을 검사합니다.
- **사용자 경계**: worker 도구는 permit의 사용자와 질문의 사용자가 같아야 합니다. 다르면 `not_found`(남의 질문을 '없음'과 구별하지 않음). permit이 없으면 `permit_invalid`.
- **저장 규칙**: 같은 `idem_key`로 다시 오면 처음 결과를 그대로 `duplicate=true`. 질문이 지워졌거나 수정됐으면(세대 불일치) `generation_mismatch`. 다른 키로 이미 답이 저장돼 있으면 덮어쓰지 않고 `generation_mismatch`.
- 담당 표시는 기존 계획대로 `T5`(입출력), 검토 `T3·T4`입니다. **계획 단계였던 `qa_context`·`qa_complete`·`web_search`의 입출력을 그래프에 맞춰 바꿨으므로 T5 확인이 필요합니다.**

## 오류 변환 (`notree/worker/handlers/qa.py`)

| 상황 | 그래프 / worker |
|---|---|
| 검색 도구 일시 거절(`unavailable`·`locked`), 연결 끊김 | `SearchUnavailable` → 노트·전사는 1번 다시, 안 되면 다음 출처 (웹은 다시 안 함) |
| 검색 도구 영구 거절(`not_found`·`permit_invalid`) — 예: 검색 중 질문 삭제 | `SearchForbidden` → `QAFatal` → `FatalError` (다시 시도 없이 실패, 다시 시도 불가) |
| 저장 거절 `generation_mismatch` — 예: 답을 만드는 중 질문 삭제 | `FatalError` |
| 저장 일시 거절 | `RetryableError` (루프 재시도. 이미 저장됐으면 다음 시도에서 duplicate로 끝남) |
| 그래프 안 시간 초과, 근거 부족 | 정상 저장 (`시간 초과`/`근거 부족`), 작업은 `done` |

마감은 `qa_ask`가 넣은 `deadline_at`을 그래프의 시간 예산과 루프의 실행 제한이 함께 씁니다 (팀 결정 2·3번: 요청부터 90초 안에서 최대 3회).
