# Q&A 실제 OpenAI 측정 (2026-10-17)

`notree.dev.qa_eval`: **가짜 검색**(`sample_corpus`, 키워드 일치) + **실제 LLM**. 주어진 근거로 답하는 능력을 보며, 실제 검색 품질은 측정 대상이 아닙니다.

## 1차 — gpt-4o-mini, 3회 반복 (이근욱 PC, `feat/qa-verify` `91caeb0`)

```powershell
uv run python -m notree.dev.qa_eval --llm openai --repeat 3 --out out/qa_eval.jsonl
```

| 사례 | 통과 | 상태 | 라벨 | 초(중앙) | LLM 호출 | 입력 토큰 | 출력 토큰 |
|---|---|---|---|---|---|---|---|
| note | 3/3 | completed | 강의 | 2.24 | 2 | 362 | 68 |
| transcript | 3/3 | completed | 강의 | 2.07 | 2 | 379 | 77 |
| web | 3/3 | completed | 웹 | 1.95 | 2 | 388 | 69 |
| unrelated | 3/3 | completed | 일반 지식 | 1.49 | 2 | 241 | 48 |
| not_found | 3/3 | 근거 부족 | 근거 부족 | 2.40 | 2 | 272 | 60 |
| partial | **0/3** | 부분 답변 | 강의 | 1.55 | 2 | 376 | 68 |
| tight_deadline | 3/3 | 근거 부족 | 근거 부족 | 0.77 | 1 | 117 | 34 |

- 21건 중 18건 통과. 문장별 JSON 형식 오류 0, 받은 근거 밖 인용 0, 문장 안 인용 표시 0. 질문당 1.5~3.5초 (LLM 2번, 호출당 0.8~1.1초 정도).
- 전사 답변의 "교수님:" 말머리는 모델이 스스로 정리함. 관련 없는 질문은 일반 지식으로 짧게 답함.
- 비용은 단가를 넣지 않아 계산하지 않음 (질문당 입력 약 120~390, 출력 약 35~77 토큰).

**partial 실패 원인** ("스택과 큐는 어떻게 다르고 각각 언제 써?"). 3회 모두 같은 모양:

```json
{"status": "부분 답변", "citations": ["n1"], "searched": ["note", "transcript", "web"],
 "answer": "스택은 LIFO 구조로, 마지막에 넣은 원소를 먼저 꺼낸다. [^n1]",
 "llm": [{"kind": "understand", "seconds": 1.121, "prompt_tokens": 160, "completion_tokens": 25},
         {"kind": "answer#1", "seconds": 0.794, "prompt_tokens": 216, "completion_tokens": 43}]}
```

- 기대: 스택 LIFO(n1) + 큐 FIFO(n2) + 큐는 대기열(t2), 스택의 쓰임새는 근거가 없으니 `부분 답변`.
- 실제: 스택 한 문장만 쓰고 "근거가 더 필요"로 끝냄. 상태(`부분 답변`)는 맞지만 **답할 수 있는 부분(큐)까지 빠뜨림** → 프롬프트 문제로 판단.
- 조치: 답변 프롬프트에 "여러 부분으로 된 질문은 부분마다 따져서 근거로 답할 수 있는 부분은 빠짐없이 모두 답하고, 근거 없는 부분만 '찾지 못했다'고 쓴 뒤 needs_more_evidence" 추가.
  측정 도구는 이제 실패한 사례의 검색어·근거(점수)·문장별 인용을 출력하고 jsonl에도 남김. → 2차 측정 대기.

**함께 본 것 (미결정)**: `tight_deadline`(마감 4초)은 기대 범위라 통과했지만, 시간이 없어 검색을 하나도 안 했는데 `근거 부족`으로 저장됩니다.
사용자에게는 "자료에 답이 없다"로 보이므로, 검색을 모두 시간 때문에 건너뛰고 인용이 없으면 `시간 초과`로 저장하는 쪽을 제안했습니다.
